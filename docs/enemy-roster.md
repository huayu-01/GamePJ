# 地面敌人清单与共通规则

2026-10-20用户需求接收。本文是清单、源码核对和后续开发约定，尚未把新怪物、攻击预警、护甲硬直或敌人寻路接入生产。当前生产仍为8种普通敌人、1种首领护卫；敌人表另有1条全局倍率，不算怪物。新增11种设计后，清单共20项＝19种普通／特殊地面原型＋1种首领护卫。首领单列，友方召唤物不计入。先不设计飞行敌人；跳扑和俯冲属于地面单位的攻击动作。

下面E编号只用于讨论，不是已创建的资源Id。已有行为直接复用；同一组件能复用，不代表整种怪物已经实现。精英附加特性后续单独设计，作为普通原型的附加效果。

## 三、优先拆出的共用行为／能力

| 模块 | 负责什么 | 主要复用对象 |
|---|---|---|
| 导航移动与严格有效点 | 路径跟随、追击／撤退／换位目的地、范围与可达性验证 | 全部地面单位，尤其地鼠、投掷兵、法师 |
| 成功起手预警 | 攻击实际进入准备时身体短闪一次，取消／结束后正确恢复 | 全部敌人攻击动作 |
| 受击与防御反应 | 普通受击硬直、护甲霸体、持盾／技能格挡硬直、护罩无硬直 | 普通敌人、精英和玩家防御机制 |
| 距离选择与分阶段序列 | 举盾后远近分支、近战／后跳／投掷、冲锋后接攻击、自动连招 | E11、E12、E14、E19、E20 |
| 攻击后重定位／遁地 | 等待、遁地、选点、出土，再攻击 | E10，可供其他换位敌人复用 |
| 抛射瞄准与弹道终止 | 抛射初速度；航程结束时消失／掉落／爆炸；命中和终止去重 | E10、E12、E18、E19 |
| 上方落弹 | 蓄满时采样位置、落点预警、上方生成下砸投射物 | E13的多种元素表现 |
| 追踪冲锋与触发后续 | 蓄势看向、冲锋转向、接近／碰撞只切换一次后续攻击 | E14；与E04固定方向策略分开 |
| 起跳→滞空→俯冲 | 通用三维动作序列，复用现有移动所有权与落地事实 | E15及未来同类动作 |
| 突进近战段 | 一段位移加命中窗口，可组成回旋或连续攻击 | E17、E20 |

Behavior决定何时、对谁、去哪里；Ability负责准备／执行／恢复和动画事件；Projectile负责弹道与终止；防御反应与表现各自独立。不为每种怪物复制一整套Brain／移动／弹道代码。

## 四、共通攻击预警

用户确认：敌人发动攻击或进入攻击准备时，身体需要短闪，远程单位尤其需要让玩家在没看清动作时注意到攻击来源。

- 从成功进入攻击准备的事实触发；失败的施法请求、冷却等待、每帧AI判断不重复闪。
- 预警是身体表现，实际伤害仍由真实执行／动画命中时机决定；预警不能提前造成伤害。
- 射击、近战、蓄力、冲锋、砸地等共用入口，连招补闪和高威胁阶段可以配置。具体颜色和时长是后续表现预设。
- 攻击预警、受到伤害的闪色、护甲常态特效和精英标识需要协调。当前UnitPresentation直接替换MaterialOverride，结束时清空；EliteModifier也写同一属性，存在互相覆盖的风险，不能继续各写各的材质恢复逻辑。

## 五、护甲与受击规则复核

用户确认的敌人规则：有护甲时不进入普通受击硬直，攻击前摇不会被普通受击打断；护甲需要额外特效＋模型缩放表现，让精英／有甲状态能够一眼识别。

源码核对：Unit.ReceiveHit已有减伤→护甲→护盾→生命、ArmorBroke事件和伤害后击退；EliteModifier已有加甲、体型1.35和染色。尚未看到按护甲状态统一区分普通受击硬直和攻击打断的完整流程，不能把“当前没有受击动画”算作已经完成护甲霸体。

后续需分别裁定普通受击、动作打断与表现：

- 护甲继续正常承伤／破甲，有甲免普通受击硬直不等于无敌。
- 命中前是否有甲、本击是否破甲、是否致死应作为同一击的事实保存，避免扣完甲后再读Armor导致判据漂移。
- 无甲敌人需要接上普通受击反应及可打断时机；死亡优先正常结算。破甲当击是否额外进入专用破甲硬直属于待定细节。
- 护甲霸体、物理质量、击退抗性和ControlImmune不是同一配置。用户本次确认的是普通受击硬直／前摇打断保护；是否额外免击退、冻结等控制后续单独确定。
- 普通受击硬直与成功格挡者自身的格挡硬直是两种反应，分别判断；有甲免普通受击不能自动抹去持盾／技能格挡动作的反应。
- 普通守卫和直线冲锋兵目前也自带护甲。是否把所有有甲敌人都归为精英，以及破甲后是否保留精英体型／词条，后续落实时明确，不能仅靠Armor>0悄悄改动精英身份。
- 模型视觉缩放与身体碰撞尺寸分别配置、验证。当前EliteModifier缩放的是Unit根节点，包含碰撞体；用户提出模型放大后，需要明确是否同步扩大身体，尤其会影响堵路和导航通行。

## 六、防御方式与格挡硬直

2026-10-20用户已明确：这里的格挡硬直指成功格挡的防御者自身硬直，不是攻击者弹刀。

| 防御机制 | 格挡者自身反应 | 说明 |
|---|---|---|
| 持盾单位的主动／持盾格挡 | 可配置格挡硬直 | 正面挡住后，防御者发生受力／短暂停顿；用于E07、E11等 |
| 技能类格挡／架势 | 有格挡硬直 | 格挡动作成功后进入自身反应；与技能后续反击、冷却事件协调 |
| 效果提供的一次性护盾／护罩挡伤 | 没有格挡硬直 | 消耗效果并给护罩反馈，不把玩家强制打进格挡硬直 |

按防御机制决定反应，不按防御次数决定：技能架可能也只挡一次，仍属于技能格挡；由技能生成的一次性护罩仍属于效果挡伤。普通护盾数值吸收伤害、护罩单次无效化、正面盾挡和主动架势应分别建模。

当前BlockComponent只算正面和伤害倍率；GuardStanceAbility走单个HitInstance无效化与Parried事实。后续不能只看DamageResult.Blocked统一加硬直，需要保留本次由哪种防御机制挡住的事实。攻击者是否有弹刀／硬直是另一个独立机制，本次没有把它追加到所有格挡上。

## 七、导航网格与“有效位置”

用户确认：敌人需要寻路网格寻路，不能靠射线避障充当寻路；大部分“有效位置”是从寻路网格上挑选的可用位置。

现状：MapManager已有NavigationRegion3D／NavigationMesh烘焙、IsReady、TrySnap、IsWalkable和RingPoint／SpawnPoint；敌人的Chase／KeepDistance仍是直接意图方向配射线侧移，Reposition会直接取随机环点。已有导航点供给不代表敌人已经会沿网格路径绕墙。

后续统一接入约定：

1. 基于现有MapManager管理导航地图。地面敌人通过NavigationAgent3D或统一NavigationServer查询取得路径，交给CharacterMovement.SetIntent／MoveAndSlide执行移动。追击、撤退、保持距离和换位都沿这条路径接入。
2. “有效位置”至少满足导航地图已同步可用、候选点在允许导航区域／层、投影偏移和高度在容差内、投影后仍满足距离范围、对应体型可站立且没有被地形／单位占满。
3. 按用途检查连通性：行走目的地需要当前单位能够走到；刷怪／地鼠出土点要与玩家所在战区满足规定的连通关系，不能仅找几何上最近却在隔离岛的网格点。遁地是否穿越地表障碍由动作设计决定，不强行等同于走路。
4. 地鼠出土、后跳落点、远程站位、法师施法站位和普通刷怪统一从该有效点接口取。范围是在投影后重新验证；不同楼层不能只按XZ距离认定“附近”。
5. 找不到有效点或导航尚未就绪时，明确失败／等待／重选，不能把玩家脚下或未验证的随机环点冒充成功。现有RingPoint的兜底策略需要迁移，不能继续当作严格有效点契约。
6. 动态单位用局部避让和身体碰撞处理，静态地形由网格路径负责；根据普通／大型／精英体积配置通行净空，不能只调Agent避让半径就假设它能走过所有窄门。
7. 射线仍可检查射击视线、短距离净空或地面，但不替代路径搜索。冲锋和俯冲攻击的轨迹由技能决定，并保留真实碰撞；不会自动沿弯曲导航路径拐弯。

NavigationAgent负责查询／跟随辅助，实际角色移动仍由项目自己的运动代码执行；这与现有CharacterMovement职责一致。[Godot官方导航代理说明](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationagents.html)

## 八、精英附加特性（后续）

按用户提出的方向，精英是在普通原型身上附加效果，后续单独列词条，不复制20套“精英版怪物”。现有EliteModifier的加数值／加甲／放大变色和EliteSkillRandomizer的护卫技能随机化，都不能当作这套通用词条已经完成。

后续结构为“敌人原型＋精英身份／护甲配置＋附加特性列表”。词条可按移动、攻击、受击、周期、死亡等事件触发；具体效果、数量上限、互斥、同屏危险预算和破甲后是否失效，等待用户下一步设计。本次不把示例游戏里的所有词条直接导入项目。

## 九、后续实施顺序与待定项

建议顺序：共通攻击预警／材质协调→普通受击与护甲霸体、格挡者自身反应→导航路径和严格有效点→共用攻击／位移／弹道模块→逐个组合新敌人→精英附加特性。导航必须先于依赖“有效位置”的地鼠、后跳和远程站位落地。

后续具体配置时再确定：破甲当击反应；护甲与精英身份／体型的绑定；追踪冲锋的碰撞伤害和后续攻击是否保留两段伤害；炸弹碰地／碰墙规则；玩家腾空时法师落弹锁定的高度处理；通用控制的时长与免疫范围。未定数值先用可调预设，不为本清单额外打断询问。

本轮只核对源码、整理清单并修正文档中的过时限制；生产敌人数量、代码和配置不变，没有把上述待实现项标为已完成。
