# 地面敌人清单与共通规则

2026-10-20按用户要求先完成地图与导航基础（J35），再接入共通战斗反应和11种新敌人机制原型（J36）。生产敌人表共21行＝1全局倍率＋20敌种；其中19种参与随机生成，1种为专用首领护卫。首领单列，友方召唤物不计入。新敌人使用胶囊占位模型与实际事件动画，最终模型、动作和特效美术后续设计。先不设计飞行敌人；跳扑和俯冲属于地面攻击动作。

E编号用于讨论；实际资源Id见下方配置表。精英附加特性后续单独设计，作为普通原型的附加效果；现有精英数值增强继续保留。

## 四、共通攻击预警

用户确认：敌人发动攻击或进入攻击准备时，身体需要短闪，远程单位尤其需要让玩家在没看清动作时注意到攻击来源。

- 从成功进入攻击准备的事实触发；失败的施法请求、冷却等待、每帧AI判断不重复闪。
- 预警是身体表现，实际伤害仍由真实执行／动画命中时机决定；预警不能提前造成伤害。
- 射击、近战、蓄力、冲锋、砸地等共用入口，连招补闪和高威胁阶段可以配置。具体颜色和时长是后续表现预设。
- UnitPresentation统一管理底材、攻击短闪和受伤闪色；预警金黄短闪0.12秒，优先于受伤闪色，结束恢复原始／精英底材。Ability成功起手触发；组合能力在每个伤害动作段触发，举盾与等待不误闪。

## 五、护甲与受击规则复核

用户确认的敌人规则：有护甲时不进入普通受击硬直，攻击前摇不会被普通受击打断；护甲需要额外特效＋模型缩放表现，让精英／有甲状态能够一眼识别。

CombatReaction接收命中前hadArmor事实。活着的无甲敌人受到非DoT、未格挡的有效伤害时进入0.18秒普通硬直，停止自主移动，并打断当前允许中断的动作、关闭命中体；有甲时免该普通硬直。模型有hit／hurt／damage动画时播放对应动画，缺少时仍有实际移动与动作反应。玩家普通受击规则本轮不扩展。UnitPresentation给有身体碰撞体的单位显示有甲外壳，随甲破隐藏；EliteModifier保留1.35体型与精英染色。

当前实施口径：

- 护甲继续正常承伤／破甲，有甲免普通受击硬直不等于无敌。
- 命中前是否有甲、本击是否破甲、是否致死应作为同一击的事实保存，避免扣完甲后再读Armor导致判据漂移。
- 破甲当击按命中前有甲处理，免普通硬直；下一次无甲命中可以打断。死亡仍优先；本轮不加独立破甲硬直。
- 护甲霸体、物理质量、击退抗性和ControlImmune不是同一配置。用户本次确认的是普通受击硬直／前摇打断保护；是否额外免击退、冻结等控制后续单独确定。
- 普通受击硬直与成功格挡者自身的格挡硬直是两种反应，分别判断；有甲免普通受击不能自动抹去持盾／技能格挡动作的反应。
- 护甲不自动改变精英身份。普通守卫、直线冲锋兵的开局护甲仍有效；精英破甲后保留精英身份、数值和体型，外壳消失。
- 保留现有精英Unit根节点缩放，包含身体碰撞；地图按最终体积验证刷怪净空，较大身体用独立通行档案，避免只放大模型却假设仍能过窄门。

## 六、防御方式与格挡硬直

2026-10-20用户已明确：这里的格挡硬直指成功格挡的防御者自身硬直，不是攻击者弹刀。

| 防御机制 | 格挡者自身反应 | 说明 |
|---|---|---|
| 持盾单位的主动／持盾格挡 | 可配置格挡硬直 | 正面挡住后，防御者发生受力／短暂停顿；用于E07、E11等 |
| 技能类格挡／架势 | 有格挡硬直 | 格挡动作成功后进入自身反应；与技能后续反击、冷却事件协调 |
| 效果提供的一次性护盾／护罩挡伤 | 没有格挡硬直 | 消耗效果并给护罩反馈，不把玩家强制打进格挡硬直 |

按防御机制决定反应，不按防御次数决定：技能架可能也只挡一次，仍属于技能格挡；由技能生成的一次性护罩仍属于效果挡伤。普通护盾数值吸收伤害、护罩单次无效化、正面盾挡和主动架势应分别建模。

BlockComponent成功正面挡伤时给格挡者调用BlockRecoil，默认0.15秒，可设0；背击、破防、穿透格挡和倍率1不触发。GuardStanceAbility在真实GuardOn后的成功挡伤单独调用同一反应；效果的一次性Negated路径不调用。不从DamageResult.Blocked统一猜测防御来源。攻击者弹刀是独立机制。

## 七、导航网格与“有效位置”

用户确认：敌人需要寻路网格寻路，不能靠射线避障充当寻路；大部分“有效位置”是从寻路网格上挑选的可用位置。

J35已接入MapManager严格TryPath／TryValidPoint／TryRingPoint与UnitNavigation。追击、保持距离、撤退、换位沿完整导航路径给CharacterMovement发送意图；生产刷怪、新敌人地鼠出土和后跳用严格选点。旧Vector3返回接口仍供历史交互／掉落调用，不把它们宣称为严格选点。

导航接入约定：

1. 基于现有MapManager管理导航地图。地面敌人通过NavigationAgent3D或统一NavigationServer查询取得路径，交给CharacterMovement.SetIntent／MoveAndSlide执行移动。追击、撤退、保持距离和换位都沿这条路径接入。
2. “有效位置”至少满足导航地图已同步可用、候选点在允许导航区域／层、投影偏移和高度在容差内、投影后仍满足距离范围、对应体型可站立且没有被地形／单位占满。
3. 按用途检查连通性：行走目的地需要当前单位能够走到；刷怪／地鼠出土点要与玩家所在战区满足规定的连通关系，不能仅找几何上最近却在隔离岛的网格点。遁地是否穿越地表障碍由动作设计决定，不强行等同于走路。
4. 地鼠出土、后跳落点、远程站位、法师施法站位和普通刷怪统一从该有效点接口取。范围是在投影后重新验证；不同楼层不能只按XZ距离认定“附近”。
5. 找不到有效点或导航尚未就绪时，明确失败／等待／重选，不能把玩家脚下或未验证的随机环点冒充成功。现有RingPoint的兜底策略需要迁移，不能继续当作严格有效点契约。
6. 动态单位用局部避让和身体碰撞处理，静态地形由网格路径负责；根据普通／大型／精英体积配置通行净空，不能只调Agent避让半径就假设它能走过所有窄门。
7. 射线仍可检查射击视线、短距离净空或地面，但不替代路径搜索。冲锋和俯冲攻击的轨迹由技能决定，并保留真实碰撞；不会自动沿弯曲导航路径拐弯。

NavigationAgent负责查询／跟随辅助，实际角色移动仍由项目自己的运动代码执行；这与现有CharacterMovement职责一致。[Godot官方导航代理说明](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationagents.html)

## 八、精英附加特性（后续）

按用户提出的方向，精英是在普通原型身上附加效果，后续单独列词条，不复制20套“精英版怪物”。现有EliteModifier的加数值／加甲／放大变色和EliteSkillRandomizer的护卫技能随机化，都不能当作这套通用词条已经完成。

后续结构为“敌人原型＋精英身份／护甲配置＋附加特性列表”。词条可按移动、攻击、受击、周期、死亡等事件触发；具体效果、数量上限、互斥、同屏危险预算和破甲后是否失效，等待用户下一步设计。本次不把示例游戏里的所有词条直接导入项目。

## 九、后续实施顺序与待定项

已按用户顺序先完成地图导航，再完成共通反应和新敌人组合。精英附加特性及额外生成压力后续设计，当前附加值为0。

可调初始预设：追踪冲锋保留接触伤害＋一次后续近战；炸弹接触敌对身体、地形或耗尽累计航程爆炸；法师在蓄满时采样玩家当前位置（含高度），从其上方8米下落；地鼠找不到合规出土点保留原处，后跳找不到落点则取消该段。自爆前摇0.9秒，无甲可被普通命中打断，有甲遵循共同护甲保护。后续平衡和最终美术不在此轮定稿。
