# 精英特性：单特性波次、接入与制作

2026-10-26依据用户筛选及补充确认实现。**33项特性已有独立资源与运行行为，已接入原冒险节点波次和暮光回廊生存模式，专项已验证。**虫洞、筑墙、飞弹减速继续暂缓，不进入抽取池。数值与表现为首版，长局平衡仍可调整；最终结果见[交付证据](../Logs/evidence/elites-delivery-20261026.json)。原始筛选位于 `F:\Godot项目\3d肉鸽雨中哈迪斯\精英特性.txt`，已同步当前状态。

## 一、用户明确的规则

1. **每只精英最多一个附加特性；同一波只选择一种特性。**同波多只精英可以携带同一种特性，未分配特性的精英保留基础精英身份。
2. 对较强特性，可把同波承载数量限制为**一只**。承载上限按特性配置；它与精英总数量、单个效果产生的节点／投射物数量分别管理。
3. **召唤不收取额外随从生成费用，只召唤一批有限数量。**不按存活数量持续补员，不因随从死亡重置额度，不预收这批随从的生成费用。
4. 虫洞、筑墙、飞弹减速暂缓，本期有效清单为**33项**；暂缓3项保留在文档中，不能进入抽取池。
5. **荆棘棋盘是接触触发的地板效果，可以跳跃躲避。**它不是实体路障，不沿用原提案“击碎荆棘开路”的定义。
6. 其余沿用本轮设计审查建议，但此前的双特性组合方案退出当前范围；不因此允许任何双特性。

## 二、波次与分配边界

- 一个波次只抽取一次特性并冻结结果；同波分批生成、延迟入场及补齐原定生成计划都沿用它，不逐只重抽。
- 先过滤适合当前模式、地图和敌种的特性，再决定承载单位。找不到合法承载者时允许本波无附加特性，不能为了凑数产生第二种特性。
- 同波承载上限覆盖该波整个生命周期；指定承载者死亡后不自动把特性转移给另一只精英。
- 普通原型已有的冲锋、追踪、举盾、遁地等能力，以及精英基础护甲／数值／体型，不计作第二个附加特性，但仍参与适配与压力评估。
- 特性产生的连线、护罩等接收效果不等于给友军安装第二个特性。召唤物不继承特性，也不再召唤。
- 原冒险按 `EncounterController` 实际波次冻结特性；同波分批出场不重抽。兼容非波次逐只生成时，以至多4只的一批管理归属。
- 生存模式由 `SurvivalDirector` 建立**至多4只原定敌人、至多20秒的一批**，阶段切换也会结束旧批；这两个值分别由 `EliteTraitBatchSize`／`EliteTraitBatchSeconds` 配置。待生成对象落地或取消后封存该批成员，不把每只敌人当作新波重新抽取。批次包含普通敌人，但只有符合条件的精英能够承载特性。
- 当前保证的是**单波一种**，不是全场永久只有一种；同一精英危险调度器内，不同批次的特性区域和遗留危险共享容量。该容量不包含沿旧入口生成的原型技能与投射物。
- 原先“强横＋重铸”“黑雾＋压制”等双词缀互斥不再作为当前抽取分支；相似矛盾仍可能来自敌种固有能力或跨波重叠，应通过适配、时序和危险额度处理。

## 五、共通执行与预算边界

- 特性通过 `EliteTraitDefinition` 创建每名承载者独立的 `EliteTraitBehavior`，`EliteTraitRuntime` 统一驱动事实与生命周期；不复制33套敌人，也不把原有护卫技能随机化当作此系统。
- 精英基础身份、护甲和附加特性分开。破甲是否关闭该特性单独规定；有甲免普通受击不等于全控制免疫，护甲也不是无敌。
- 本体和特性的生成费用、同波承载上限、存活数量上限、同屏危险额度分别管理。携带特性的精英消耗原型费用加 `ExtraCost`，生成成功才扣费；失败释放预留，不浪费承载名额。即时资源短缺时等待，剩余总预算或预算／压力硬上限无法容纳附加费用时可回退为基础精英。
- **召唤随从免费，不预扣、不另收费**；但按敌种基础压力加入存活压力、人数和清场统计，受存活上限约束。生存模式为随从标记 `EliteSummoned`，排除经验、猎令候选／完成及遗物收益，避免免费召唤形成收益循环。
- 生命链接、庇护等同词缀多承载者也要限制连接数量、授予频率和循环保护；“同波只有一种”不等于可以无限叠同一种。
- **本期容量只覆盖 `EliteHazardWorld` 管理的精英特性区域：每个调度器总上限24个、每来源上限6个。**熔火遗爆、已启动节点等死亡后危险持续到期前仍占名额。原型的 `EnemyPlan` 技能、普通投射物与既有攻击盒继续使用原系统自身限制；跨原型攻击与精英特性区域的全场统一额度尚未接入，不能把本期24个上限理解为所有战斗危险的总量。
- 新效果遵守现有攻击快照、命中去重、阵营过滤、有效伤害与死亡归属契约。无敌／护罩抵消不能给蓄压和吸血提供虚假有效伤害。
- 自然死亡允许的遗留危险与主动清场分开。奖励选择期间暂停伤害和危险计时，选择结束后继续；成功清场开放交互、取消、结算、阶段终止与场景退出则统一撤销相关伤害、订阅和来源效果。暂停不推进计时。
- 荆棘棋盘制作验收至少覆盖接地触发、空中越过不触发、落地触发、离开后不重复误触、重叠区域频率限制及暂停／清场撤销。
- 首领继续沿用独立技能构筑和既定常驻霸体，不自动抽取这套普通精英特性。

## 六、制作与验证入口

- 显式目录为 [catalog.tres](../Config/EliteTraits/catalog.tres)，33个定义与参数行位于 `Config/EliteTraits/`；两个生成导演共用该目录，`EnableEliteTraits` 可关闭附加特性供对照。
- 行的 `Id`／`NameKey`／`DescriptionKey` 是稳定身份；显示名不参与安装行为。`ExtraCost` 是承载者额外费用，`MaxCarriers` 是同波成功承载上限，`Requirements`／`Supports` 筛选适用原型，`PreSpawnScale` 在导航选点前就计入最终体型。
- 参数定义位于 `Scripts/Combat/Elites/Definitions/`，行为按属性、防御、机动、投射和危险等职责组织。扩展时复制相近定义和资源，由 `Create` 创建独立行为，加入显式目录；共享资源不保存本局计时或持有者。新行需维护目录的 `ExpectedCount` 和对应专项数量。
- [_tools/build_elite_traits.py](../_tools/build_elite_traits.py) 是本批制作脚本，显式执行会重写它拥有的定义、33行和目录；日常调参不要无意重跑。文本同步使用 `_tools/sync_content_text.py`，已经支持精英名称和说明。
- [验证入口](../_tools/verify_elite_traits.ps1) 提供 `EliteDefense`／`EliteHazards`／`EliteMotion`／`EliteIntegration` 四专项及无头／渲染两种运行方式；共享验证锁、隔离用户目录及真实存档指纹检查。防御分摊、跳跃避开地板、地板／激光真实地形裁切、取消前摇不生余震、同波分配、免费有限召唤、原节点和生存接入及清场已有专项验证。最终四类无头／渲染共8次运行、435项断言通过，分别为防御70／71、范围60／66、机动53／54、双模式集成30／31；见[逐项交付索引](../Logs/evidence/elites-delivery-20261026.json)与[验收目录](../Logs/evidence/elites/)。19项原流程、65／69项生存专属构筑、补跑动作中断38项及7次GC均通过，双构建0警告0错误，311条文本无待同步，真实五存档未变化。
- 旧中断测试的固定墙钟取样已改为观察真实动画时间轴，保留0.2秒解锁阈值与原断言；失败和复测日志均保留。
- 冷却、伤害、范围、承载人数和危险容量是首版可调预设；专项通过不等于已经完成12分钟长局人工平衡或最终美术定稿。
