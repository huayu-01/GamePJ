# J30：持续伤害来源与逐杀事实（2026-10-18）

修正燃烧Tick没有攻击者、Context.OriginalSource为空，因此目标虽被烧死，却不产生本人Kill、灵魂收割或死铠收益的问题。[修复前实测](character-design-j30-failure-20261018_223442.log)为1通过／5失败；原六项修复后全部通过，再扩展到26项。

ActiveStatus保存最近一次施加者与来源技能身份。Unit.ReceiveHit附加状态时透传命中来源，BurnOnHitRule也明确透传自身玩家；增益光环、刹那之眼、标记增幅与飞弹信标的直接施加入口一并补齐来源参数。无来源旧调用保持兼容，未知来源刷新清除旧归属；同名状态刷新／叠层时，后续伤害归属于最近一次施加者。来源已释放时安全降为未知，不猜测其他玩家。

每次Tick建立独立的`Status:<状态Id>`攻击身份，保留施加技能AbilityKind，带IsDamageOverTime标记及实际世界位置。伤害继续走原ReceiveHit、无敌／防御／受伤／死亡入口；固定DamagePerSecond没有改成再乘玩家攻击力或暴击，不复制原攻击的连招段号，也不附带原Status而递归再施加。计时、层数、DPS数值沿用既有规则，本批不是DoT平衡或计时重写。

Hit／Damaged／Died／Kill事实透传DoT标记。恢复Source以后，Hit不能被误当成新主攻击：TriggerRule缺省忽略DoT的Hit触发，仍接受Damaged／Kill；有明确需要的规则可以单独开启IncludeDamageOverTimeHits。这样燃烧不会因为自己的Tick永久刷新自己，标记等主攻击规则也不被无意多触发。架势同样排除DoT，保留此前来源为空时无法将持续伤害算作一次新招架的行为。灵魂、死铠与践踏死亡继续消费真实Kill，无需另写DoT专用收益分支。
