# 奖励、构筑与成长

本文记录当前抽取和效果契约。旧枪械奖励、三角色限定、P5／P6逐项接入及历史截图见 [历史原文](archive/reference-before-2026-10-21/rewards.md)。当前内容清单与验证状态见 [开发快照](SESSION-SNAPSHOT.md)。

## 三层局内奖励与局外配置

| 层 | 作用与来源 |
|---|---|
| 强化 Enhancement | 属性与既有能力参数增强；是否可重复由行内获取次数规定 |
| 进化 Evolution | 改变当前攻击方式；通过武器专属池或标签限定 |
| 异化 Mutation | 增加触发、召唤、拾取或其他规则 |
| 符文携带 | 基地选择，一次一枚，可不携带；独立于局内奖励目录，提供效果及特化前置 |
| 能力卡 | 局外解锁、升级、激活与额度；出击配装应用 |

特化使用现有奖励／规则体系，不额外绕开候选过滤。当前91项局内奖励、11枚符文和23项特化的批次来源见快照；数量不要分散复制为新的硬编码判定。

## 候选池与抽取

配置行由 `RewardConfig.Compile` 等入口编译为 `RewardDefinition`，目录由 `RewardCatalog` 提供。

1. 进入关卡、角色与武器确定后，`RunController.InitializePool` 调用 `RewardPool.Initialize(weapon, characterId)` 建立候选集。
2. 角色层按 `RequiredCharacterIds` 匹配稳定行 Id；未知角色不能获得角色限定项。旧 `SummonerAllowed`／`RequiresSummoner` 已移除。
3. 武器层依次判断专属 `ApplicablePoolIds`、`RequiredWeaponTags`，两者均无则通用。专属池已填时不再回落到其他武器。
4. 每次 `Roll` 读取当前构筑，过滤节点类型、前置、互斥、获取次数，然后按 `Weight` 不重复加权抽取；候选不足时不会凭空补出失效内容。
5. `RewardScreen` 暂停并提供选择；确认后 `RunBuild.Add` 记录层数、应用效果，随后回调关卡启动挑战。

“武器限定池”是进化的限定关系，不是单独的生产节点类型；三关内候选来源由本局配装确定，依赖已获得内容的条件每次抽取重算。

| 条件 | 当前规则 |
|---|---|
| `Requires` | 必须全部满足；统一经 `RunBuild.SatisfiesPrerequisite`，来源包括已获奖励和携带符文 |
| `Excludes` | 双向互斥：候选排斥已有项，或已有项排斥候选，都排除 |
| `ConflictsWith` | 候选声明的单向冲突 |
| `MaxStacks` | 0不限、1一次、正数为获取次数上限；达上限退出候选 |
| `+`／`++` | 有上一级前置；仅需求中允许重复的条目配置可重复获取 |

## 节点收益

`NodeConfig.RewardBehavior` 指定选择、资源、治疗或商店策略，`RunController.OpenRewardForNode` 只提供本局服务和挑战编排。强化／进化／异化筛选对应奖励，特殊节点只提供一次选择；候选种类遵从节点的`AnyRewardKind`，继续检查前置、互斥和角色／武器限定。材料、治疗比例和商店价格均由各自策略配置。商店实际领取后才完成，窗口拒绝或取消待领取购买会退款。

是否随后挑战由节点 `SpawnsEncounter` 决定。收益领取在前，挑战在后；不能将其描述成“清场后发三选一”。降临节点不进入奖励系统。战斗、隔离次数和节点代价见 [关卡流程](stages.md)。

## 效果与事件生命周期

- 全部生产增幅和符文使用 `Effects`；属性效果按来源安装 `StatModifier`，技能增强通过 `AbilityRewardTuning` 子类引用目标技能。新行为只需增加定义与实例，不扩充中央处理器清单。
- 描述经 `DescriptionTemplate` 解析，数值直接读取实际效果与参数资源；`Modifiers` 等旧属性只兼容读取，不重复保存一套参数。旧 `ApplyHandler`／`HandlerParams` 留在兼容层，生产行不再使用。
- 组合先应用再提交，失败逆序回滚；持有者按奖励来源撤销订阅、临时区域和参数租约。正常移除不追缴一次性护甲，已发射攻击沿自身生命周期结束。具体制作步骤见[内容制作指南](content-authoring.md)。
- 通用 `TriggerRule` 的条件与执行走事实总线，包含冷却、每事件链次数和链深度约束，限制递归攻击。
- 纯击杀计数、续时和拾取规则可独立订阅本人事实，不套会错误拦掉计数的攻击链门；须成对订阅／退订并按来源过滤。
- 换装、死亡或重新出征按对应生命周期清除旧规则和修饰；派生伤害、DoT 与召唤物不得冒领本人击杀。
- 起跳触发读取真实 `JumpStarted`；地面技能命中读取真实落地／事件。不要将旧“轮询落地边沿”的历史描述复制到当前起跳规则。

新增条目的表字段、限定与验收见 [增幅接入](upgrades.md)、[配置表](config-schema.md)。符文效果使用独立来源，与普通局内构筑分别清理，见 [符文系统](rune-system.md)。特化接收清单见 [后续构筑](followup-build-updates.md)。

## 当前体验边界

候选过滤正确不代表构筑一定能及时形成。当前没有证据证明所有流派在一局内都能稳定经历核心、配套和成形三个阶段；需要真实出征记录来验证出现频率、说明可读性和关键选择的效果。

符文页的可发现特化预览已按实际角色／武器候选限制过滤；基地练习尚不完整应用携带符文，携带效果进关施加。整局累计收益、跨关记录和结算去重已通过 [J44专项](archive/development-batches/character-design-j44.md)，构筑出现频率与成形节奏仍需完整试玩。
