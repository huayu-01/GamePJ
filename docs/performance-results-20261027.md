# 性能实施与验证记录

日期：2026-10-27。范围：用户批准的分配／资源查询、空闲表现更新、拥挤避让对照和模型成本诊断。保留手动战斗、现有AI决策频率、阴影、模型／骨骼源和生产刷怪数量。

## 已实施

1. 事件总线在订阅变化时生成不可变快照，广播不再反复GetInvocationList。保留多播委托、重复订阅、最后一次移除、广播中增删、重入和逐订阅者异常隔离。
2. 刷怪存活清理复用移除缓冲，构筑命中分发缓存规则快照；特化命中使用双缓冲，回调新产生的主命中留给下一帧，不被收尾清空吞掉。
3. 持续力／高度限制改为值类型记录。没有外力时跳过法线点积必为零的碰撞结果读取；MoveAndSlide、重力、落地恢复与有外力的碰撞消解仍逐帧执行，不是静止敌人物理休眠。
4. 通用子树查找、体型扫描、状态表现扫描减少临时Godot集合。导航净空检查按地图复用胶囊、查询参数和排除缓冲，仍每次查询实时占用与当前体型；地图退出释放自有资源。
5. CombatReaction只在受击／格挡硬直期间计时。UnitPresentation按闪色／攻击预警唤醒，通过护甲变化事件更新外壳。StatusEffectFx通过状态变化唤醒；IStatusVisualSource独立来源保持原轮询，动态挂载／移除可唤醒和休眠。
6. 骨骼、攻击动画、技能冷却／充能和后台能力没有统一降频或停用；没有实施先前排除的AI降频、阴影限额和静止移动休眠。

## 地面敌人避让与回退

配置入口：`Config/EnemyCrowd.tres`，由ConfigIndex统一引用。当前 `Mode=2`：

|Mode|含义|
|---:|---|
|0 Physical|原敌敌身体阻挡，不注册动态避让代理|
|1 PassThrough|取消敌敌身体阻挡且无避让，仅供对照；实测出现明显重叠，不推荐实战使用|
|2 Avoidance|取消敌敌身体阻挡，使用NavigationServer3D地面RVO避让，当前默认|

保留玩家—敌人、单位—地形与所有攻击／弹道筛选。飞行单位保留原身体规则。不同体型继续使用各自路径网格，但共享一个地面避让map；当前位置、半径、暂停、死亡、瞬移和场景退出按生命周期同步。普通移动应用安全水平速度，垂直运动与技能位移仍归CharacterMovement。截图发现模型外轮廓仍偏挤后，将避让半径从身体半径的1.12倍调整为1.4倍；只调整局部避让距离，不扩大物理胶囊。

前摇站定、受控、冲锋等单位仍作为避让对象，普通走位者优先让行。配置Changed可在运行时切换普通身体策略；资源Mode回到0可恢复原碰撞，不需要恢复源码。当前没有转为50单位或增强敌人数值，50仍是条件性回退。

首领冲锋独立扫过同阵营小怪，每次冲锋每目标最多推一次。推力有独立水平通道，可影响正在执行普通速度覆盖的小怪，不造成伤害、破甲或受击硬直，保留质量、抗性与首领免控。可通过 `BossPushEnabled` 单独关闭。

## 4K实渲染对照

RTX4070Ti、Ryzen7 5800X、Godot4.7.2、D3D12。实际输出3840×2160，3D比例1，无MSAA。真实生产死战场景／导演、近战＋远程＋重击混合，额外生命维持人数，保留AI、技能与物理；每轮暖场3秒、采12秒，用户编辑器保留。种子固定，仍存在运行时调度、冷启动和短样本波动，不把单轮结果当成稳定上限。

作用域证据：刷怪清理与无状态StatusFx在该场景的分配降为0；普通Movement作用域从约33.9MB降为0。EventBus作用域仍可能包含订阅者分配，不能误称整个事件系统零分配；单独10000次空操作广播实测由专项记录。嵌套作用域不可相加当作总耗时或总分配。

### 拥挤策略独立对照，新增净空参数缓存前

深度重叠定义：单位高度差不超过1m，水平中心距小于两身体半径之和的80%；每0.2秒取样。只衡量身体穿叠，不代表动画、武器和特效外轮廓完全不相交。

|人数|模式|平均FPS|1%低帧FPS|平均深度重叠对数|12秒分配MB|
|---:|---|---:|---:|---:|---:|
|50|原碰撞|197.3|31.7|0.0|47.8|
|50|无碰撞无避让|220.1|34.9|55.1|54.6|
|50|无碰撞＋避让|201.0|32.5|0.0|47.5|
|100|原碰撞|75.8|11.8|0.0|37.3|
|100|无碰撞无避让|106.9|16.3|205.8|50.5|
|100|无碰撞＋避让|81.1|12.8|0.0|38.9|

结论：只去碰撞会明显叠怪。避让消除了本次深度重叠，性能与原碰撞相近，不能当作主要性能来源。没有证据要求立即舍弃首领推挤，也没有据此修改生产数量。

这些基准包含开始实际攻击后的冷启动表现。100避让样本最大约249.83ms发生在第3帧，当帧无GC；12个超过33.33ms的帧中3帧记录到GC。同帧关联不能证明GC因果，其他长帧仍需继续定位。没有丢掉前几帧来宣称稳定60。

### 最终版本复测

在加入净空参数复用后，原碰撞为70.17平均FPS／11.63低帧、36.47MB分配。避让半径1.12倍时为78.52／13.30FPS；截图复查后扩大为1.4倍，最终配置为 **74.33平均FPS／12.61低帧、37.15MB分配**，p95／p99帧时18.32／44.68ms，最大249.21ms，平均深度重叠对数0。最终15项避让专项再次通过。

参数复用未显示出可独立归因的帧率收益，保留其资源生命周期与分配改进，不把不同短样本波动包装成确定加速。当前默认采用更宽松的模型间距；100敌人1%低帧仍未达60。最终证据是 `performance-tuned_100_Avoidance-20261027_011656.json`，前面的1.12倍试验不代表最终配置。

## 模型、骨骼和渲染诊断

取当前三种敌人的100个模型子树，在同一死战场景中隔离AI／技能，仅播放待机。共有100个AnimationPlayer、469骨骼、167个Mesh及167表面。只操作诊断副本，不改原模型资源或实战动画逻辑。

|阶段|平均帧时ms|p99帧时ms|GPU均值ms|draw calls|
|---|---:|---:|---:|---:|
|可见，动画播放|2.42|3.84|2.03|850|
|可见，暂停动画|2.47|3.72|2.10|850|
|隐藏，动画播放|2.39|3.53|2.06|537|

隐藏副本降低绘制次数，但当前模型规模下，暂停待机动画或隐藏模型没有给出足以支持牺牲动画表现的帧时收益。TimeProcess监控出现与实际帧时不一致的波动，未用其差值宣称骨骼耗时。该诊断不能代表复杂攻击动画、未来最终模型或大量战斗特效。

因此保留现有自动LOD导入、材质和动画事件规则，不改最终模型源，也不把完整敌人重写成RenderingServer RID。Jolt和自动视锥剔除原本已启用，不列为本次新增优化。
