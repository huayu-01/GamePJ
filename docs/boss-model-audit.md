## 实测范围与结果

- 同一引擎 **Godot 4.7.2 mono / D3D12 Forward+ / RTX 4070 Ti**。独立工程原生FBX导入6/6，退出0，无导入错误；实际渲染退出0，错误日志为空。
- 六个文件均没有AnimationPlayer动画列表，FBX也没有AnimationStack/AnimationLayer。**Mixamo兼容不等于已经附带动作**。
- 六个都没有CollisionObject3D。正式接入应保留项目既有CharacterBody3D、身体Shape和能力AttackHitbox，不能把FBX当作含碰撞的预制体。
- 已检查所有导入顶点的蒙皮权重：零权重点0，权重和偏差超过0.01的点0。基础Hips/Spine/Head/四肢链存在，前臂命名例外如上表。
- 六个均进行了运行期抬右臂探针，手骨世界位移约0.21～0.31m；SHOGUN保存了对比实拍，说明本地骨架可驱动。**这不是Mixamo真实片段的重定向验收，也不代表已验证动作穿模、脚滑、连招或伤害时机**。
- 各模型64～83骨，标准命名骨占46～52，另有18～36个装饰/机械/武器骨。重定向时要保留附属骨与父级关系，不能直接覆盖成统一骨架并丢弃它们。
- 没有外部贴图引用；使用顶点色与材质色，未发现丢贴图错误。原始颜色可正常显示。烟、光圈、信息环是网格，不会自动变成粒子、透明烟雾或发光效果。

## 尺寸与碰撞对位的坑

蒙皮模型的 `MeshInstance3D.get_aabb()` 是原始网格空间，不等于最终骨骼变换后的可见范围。
例如DRIZZEL原始网格矩阵计算的高度约0.009m，而骨骼实际驱动后的完整视觉高度约2.12m；直接拿前者缩放会让模型巨大到遮满屏幕。
检查工具已按“骨骼全局rest × Skin绑定姿态 × 权重顶点”重新计算，数据见 `boss-model-audit-summary.json`。

| 模型 | 蒙皮rest完整范围宽×高×深（m） | 最低Y（m） |
|---|---|---:|
| DRIZZEL | 1.841×2.115×0.972 | 0.000 |
| GEKKOU | 1.645×3.514×1.788 | -1.313 |
| KASA | 2.729×2.146×4.301 | -0.001 |
| KURENAI | 1.421×2.210×1.421 | -0.002 |
| SAMIDALE | 1.242×1.664×0.753 | -0.006 |
| SHOGUN | 1.326×2.624×0.607 | -1.009 |

这些是**包含武器、披风、烟与头环的完整范围**，不是角色身体尺寸。GEKKOU/SHOGUN的刀具使下界明显低于脚部，按最低Y抬起整个模型会让人物悬空。
接入时应按脚骨/脚底网格与头部标定身体，单独检查刀和披风；保持战斗根节点尺度1，只缩放纯Model子树。

当前 `Scenes/Enemies/Boss.tscn` 的身体是半径1、高2.8的胶囊，中心Y=1.4；近战与冲锋命中盒为3×2.4×3，偏移分别为(0,1.2,-1.6)/(0,1.2,-1.8)，尖啸范围半径7.5。
这些是既有玩法判定，不能为了包住尾巴、刀尖或光圈就一起放大。换模型后还需按真实动作逐帧检查握持点、刀尖轨迹、前摇及命中窗口。
现有首领近战能力由Windup/ActiveTime驱动AttackHitbox；只塞入一个带动作的模型不会自动把动作帧与伤害窗口对齐。

## 后续接入顺序

1. 首先用SAMIDALE验证Idle/Walk/Run/Hit/Death的真实Mixamo片段导入与原地播放；若优先刀剑近战形象，则选SHOGUN并先处理握刀和脚底标定。
2. 配置SkeletonProfileHumanoid/BoneMap，处理GEKKOU与KURENAI的前臂别名，保留额外骨。动画轨道还要重定向到新模型的Skeleton路径。
3. 将Root Motion与CharacterBody3D移动的职责统一，避免动作把模型拖出碰撞体；跑步/转身/死亡都要实拍。
4. 保留现有身体碰撞与AttackHitbox，通过真实攻击动作校准事件帧和有效窗口，再测早帧不伤害、有效帧命中、结束后不命中和同段不重复伤害。近战连招另外验证逐段动作、逐段命中、缓冲与收招。

本轮没有实际Mixamo动作文件，因此上述动作、攻击盒与连招仍是**未验证项**，未声称“已可直接上线”。
