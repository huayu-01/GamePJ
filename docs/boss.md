# 首领、技能与压力

首领复用 `Unit + Behavior + Ability + Modifier`，没有独立伤害基类。本文只记录现行机制；旧200护甲、旧混合池及当时日志见 [历史原文](archive/reference-before-2026-10-21/boss.md)。

## 首领本体与血量阶段

生产首领为 `Config/Tables/Bosses/boss_final.tres`，场景为 `Scenes/Enemies/Boss.tscn`。表内基础值：生命900、起始护甲0、移速3.6、击退抗性1。实际出场还叠加全局／关卡倍率、阶段、开场技能与数值词条，不能把900当作所有关卡最终血量。

| 阶段 | 生命阈值 | 能力 |
|---|---|---|
| 1 | 从满血开始 | 近战挥击 |
| 2 | ≤65% | 解锁范围尖啸与冲锋 |
| 3 | ≤33% | 解锁召唤，继续保留前阶段能力 |

`BossPhaseController` 按组件阈值切阶段，移除自身旧修饰后应用新阶段修饰，避免重复累计；能力是否可用仍由真实 Ability 状态决定。

**首领默认无甲**，Pressure 生产池没有加甲词条。护甲仍是所有 Unit 的通用属性；普通精英的 `EliteModifier` 与首领压力体系分开。旧记录中的200／350护甲属于历史状态。

## 三种强化来源分别计算

| 来源 | 入口与配置 | 当前语义 |
|---|---|---|
| 开场技能（Boss Build） | `BossPerkCatalog.Roll(BossPerkCount)`；`Config/Tables/Skills/bhv_*.tres` | 出生时按权重抽不重复的行为／技能项；三关数量当前1／2／3 |
| 节点数值词条（Pressure 转换） | `StageController.AddPressureForNode` → `RollPressure`；`Config/Tables/Pressure/` | 超额挑战正常完成后累积点数，跨阈值立即抽取，首领出生时套用 |
| 首领战计时压力 | `BossPressure.InitialLevel` 及组件计时 | 初始等级来自超额挑战次数，开战后按时间提升伤害／攻速／移速，并可按配置生成增援 |

界面统一称行为型为“技能”、数值型为“词条”，分别以 ◆／◇ 标识。`BossPerkText` 为 HUD 和预览共用文案入口，同名折叠，长列表折叠显示。

### 节点 Pressure 的顺序

1. 挑战开始计入次数；免费额度内挑战完成后直接返回，不累积点数，不执行节点额外词条抽取。
2. 超额挑战清场后，基础点数依次取节点行 `BossPressurePoints`、关卡对应价值层字段、全局默认；中低价值关卡字段≤0表示不加。
3. 乘本关 `PressureGrowthMultiplier` 以及进化／异化的类型比例。
4. 每跨一个 `PressureThreshold` 抽一次数值词条；一次跨多次就多次抽。结算后不足阈值的余数清零，不结转。
5. 节点 `BossModifierTags` 优先于关卡 `PressureUpgradeTags`；两者均空时不限制。抽到的词条排队，首领出生后按限定词判定；不适用则换抽。

当前生产数值池7项：伤害、攻速、生命、移速、尖啸冷却、冲锋伤害、召唤冷却。技能参数词条还要求首领确有目标技能；不得将其与开场技能池合并。

首领初始计时压力为 `max(0, ChallengesUsed - FreeChallengeQuota)`。节点点数转换已独立产生数值词条，不能再把同一份点数重复加到初始压力等级。

## 登场、护卫与白板副本

开门后普通 Encounter 停止继续生成，首领按本关倍率、开场技能和排队词条出场，并生成护卫。当前三关仍复用同一首领基础场景，以倍率、护卫和技能数区分。

白板首领副本是普通挑战末尾的独立阶段：当前 `EliteBossMinWave=8` 按**本关累计已开波数**判门槛；未达门槛直接结束普通挑战，达到门槛后仍须满足副本生成条件。副本使用首领表 `EliteCopyHealthScale`（当前0.35），不带完整首领战的压力、开场强化和护卫。门槛0表示关闭门槛限制，不代表禁用副本。

主首领与开场护卫已使用导航、连通性和实际体型净空选点，护卫之间也保持间距；所有位置成功后才一起入场，失败则等待重试。其他召唤／增援按各自路径维护，不能用开场选点验证替代全部增援验收。

首领技能召唤与压力升级增援也使用严格导航／连通性／身体净空选点，同批预留点避免碰撞同步前重叠。压力增援选点失败保留数量，每0.3秒重试，首领死亡撤销待生成项；技能召唤只计成功数量，未生成部分不转成跨技能生命周期的延迟队列，下一次施法重新尝试。召唤敌人同样先套敌人表再进树，之后施加一次全局倍率。此处不替代其他奖励／特化召唤路径的专项验收。

## 结束与界面

首领死亡后清场并降临交互节点，落地后互动才推进；`ChallengerActive` 必须解除，离场交互不能被自身挑战闸门锁死。当前出口主要沿用首领门位置，不跟随可能被打出地图的首领尸体。

首领门打开即封闭剩余普通节点；首领结束后冻结阶段记录与游离刷怪，只保留离场；末关出口明确返回基地。上述边界已通过 [J44自动化流程验证](archive/development-batches/character-design-j44.md)。统计、换关和结算的唯一说明见 [关卡流程](stages.md)。

默认 B 打开首领状况面板，查看隔离次数、Pressure 阈值转换、技能／词条和当前首领状态；面板通过 `OverlayScreen`／`UiRouter` 暂停并释放鼠标。

专项与 Main 证据见 [测试](testing.md) 和 [当前快照](SESSION-SNAPSHOT.md)。历史机制日志不等于本轮完整首领体验已经实测。
