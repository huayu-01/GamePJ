# 场景符文：首版接入与验收

2026-10-27，对应验收单031。首版仅接入死战模式。

## 玩法规则

进入一场死战时，从该模式配置池中加权抽取一枚场景符文。整场固定这一种，阶段切换不会重抽，也不会同时出现另一种场景符文。同种符文可以按配置周期生成实例，受实例数量上限约束。这与玩家携带符文独立，不占用玩家符文槽，也不进入增幅奖励池。

死战顶部信息栏显示场景符文的图标、名称和完整效果说明。名称和说明使用中英文本地化消息，说明参数直接来自资源，改数值后无需另改UI文案。图标为可替换SVG，场景效果目前使用基础发光球与地面范围图形。

暂停时计时和结算冻结。取消冒险、离开或重进关卡会回收实例、临时护盾和地板增伤；击败终局首领进入撤离阶段后也停止触发。

## 配置与扩展入口

- `Config/Tables/SceneRunes/`：每枚符文一份 `SceneRuneDefinition` 资源，可修改周期、预警、颜色、半径、数值及图标。
- `Config/Modes/twilight_survival.tres`：`SceneRunePool` 配置可抽取的场景符文；权重在各资源内。`FixedSceneRune` 可用于编辑器指定一枚，留空时正常随机。
- `Config/ConfigIndex.tres`、数字身份账本和 `Config/Validation/content_inventory.tres`：新内容注册和数量校验。
- `Config/Localization/zh.tres`、`en.tres`：名称与参数化说明。
- `Scripts/Run/Survival/SceneRuneController.cs`：统一生命周期；`SceneRuneMissile`、`SceneRuneField`、`SceneRuneMeteor` 分别负责三种表现和碰撞行为。

新增同类符文优先复制资源并分配新数字身份，配置参数和文案即可。新增完全不同的机制时，再扩充行为类型及专项验证。不要将场景符文塞入玩家符文或增幅的处理器。
