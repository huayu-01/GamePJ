# 构筑库存、GM获取与特殊奖励修复

本轮对应需求第3、4、8项。2026-10-24用户澄清：仅UI不显示增幅堆叠，原获取和叠加规则保持。当前力量／护甲／快速仍可重复，其他项目沿用原唯一性和前置。

## 构筑面板

- 左半为库存图标格，右半为可滚动的名称、效果描述、其他信息。两列各占内容宽度一半。
- 悬停、鼠标点击和键盘焦点均选择对应增幅，选中格外侧蓝白光圈持续显示。
- 所有增幅格子均不显示层数角标；名称和完整描述在详情显示。汇总只显示增幅项数，HUD和结算构筑摘要也不显示层数。
- 其他信息包括分类、前置及当前满足状态、互斥、角色限定、武器限定，不显示持有层数和上限。稳定ID优先换成配置中的名称；未知前置保留原文本。
- 原面板每帧销毁并重建所有格子，悬停和焦点不断被清空。现只在构筑或符文前置变化时刷新，并保留当前选中。

## GM增幅列表

GM打开后默认显示可获取增幅页，按全部／强化／进化／异化分类，可搜索名称、描述或ID。关卡内点击即经 `RunController.TryAcquireReward` 进入真实 `RunBuild.Add`，刷新可获取列表；成功消息与卡片提示不显示层数。原可重复项仍可继续点击获取并真实增加效果。

浏览和随机奖励共用 `RewardPool.Available` 的资格判定：角色、武器、前置、互斥、层数及正权重。点击时重新检查，避免列表过时后授予无效项。浏览不推进随机抽样序列。原命令区及明确的GM `give` 强制授予保留，列表正常获取不借用跳过限定的入口。

## 特殊池当前规则与历史根因

2026-10-24后续要求：特殊奖励只领取一次。已移除原第二轮抽取回调；一次选择后关闭面板并完成节点，重复输入不再授予。以下第2／3项记录原连续选择故障，通用动画保护保留。

1. `node_special` 已设置 `AnyRewardKind=true`，但原 `OfferRareRewards` 硬编码进化／异化，忽略节点配置。现在通过 `RewardService.FilterFor(Special)` 读取表，当前角色／武器符合条件的限定项与其他类型可进入池；不解除前置、互斥或限定本身。
2. 第一轮选择执行 `RewardScreen.Close` 后，同帧回调再次打开同一个面板。旧关闭Tween在稍后完成时把已重新打开的Root隐藏，而路由仍持有该模态，所以玩家看到卡死。`OverlayScreen` 现在在新的开合开始前取消旧Tween，旧关闭回调不能再隐藏新页面。
3. 第二次候选耗尽时，旧回调忽略false，节点完成链断开。现第二次没有可获取项时直接完成节点；第一轮本来就空池仍拒绝开启。
4. 奖励页清理卡片时先摘除再延迟释放；关闭或非顶层页面不再接受选择，避免被GM或其他界面覆盖时穿透操作。
