## 3. 铁律（⚠️ **每条都有栽过的例子，别当建议看**）

### 3.1 改代码

| 铁律 | 栽过的例子 |
|---|---|
| **改 C# 一律用 `edit` 工具做定点替换；绝不用 PowerShell 多行替换** | 一条 `-creplace` 把字面量 `\bBalance\b` 写进 **29 个文件**，靠 `git checkout --` 全量恢复。**栽过 7 次以上** |
| **编译必须 `--no-incremental`，且要求 0 warning / 0 error** | —— |
| **行尾 LF、无 BOM** | —— |
| ⚠️ **`.tres` 的 `Note` 里写双引号必须转义** | **未转义的双引号 → 整份 `ConfigIndex.tres` 解析失败 → 全数值静默回退**（玩家生命 250→160） |

### 3.2 `ConfigIndex.tres`（**头号风险文件**）

**它是所有表的唯一汇聚点**（~190 个 `[ext_resource]` / 12+ 个索引数组）。

**加/删一行必须"三处同改"**：

1. 顶部加/删 `[ext_resource]`（**编号取现有最大值 +1，别动别人的编号**）
2. `[resource]` 里对应的**数组加/删项**
3. **`load_steps` 跟着改**

**少改一处 → 整份加载失败 → 全数值静默回退**（**项目栽过：玩家生命 250→160，而且不报错**）。

**改完立刻验证**：日志里必须有 `（ConfigIndex.tres 已加载）` + 计数符合预期。

### 3.3 `.tscn` 手写的三个坑

| 坑 | 症状 |
|---|---|
| ⚠️ **`parent` 必须引用"已定义过"的节点** | **节点被静默丢弃**（不报错、只是不显示）。**我修 UI 浮层卡了 3 轮**，根因就是 `Overlay` 定义在引用它的子节点**之后** |
| **同一场景不能有两个同名节点**；改实例已有的子节点要写 `[node name="X" parent="..." index="0"]`（**去掉 `type=`**） | Godot 报「引入节点的名称与场景中已有的 X 冲突」。**修过：8 个 `MeleeStrike` 实例各自新增同名 `Shape`** |
| **`NodeName`（技能行 → 场景节点名）在同一场景里必须唯一** | **角色 A 的 `AbilitySkill1` 与角色 B 的撞过** → 一屏加载错误 |

### 3.4 理念（⚠️ **用户本轮刚澄清，容易理解偏**）

> 用户原话：「我倒没要求"**加内容不改代码**"，而是要求**尽量避免后期增加内容时改代码，但该改的时候还是得改**」

**所以**：
- **表驱动是"让加内容变便宜"的手段，不是"禁止改代码"的教条**
- ⚠️ **如果为了维护"不改代码"而让数据变得难懂/脆弱**（**约定路径、字符串解析、按名字查属性写错才告警**）→ **本末倒置**，**宁可老实加一个表列 / 改一次 C#**
- ⭐ **真实教训**：P4 为了绕过"新表列读不到"（**真因是编辑器加载了旧程序集**），搞了一套「**一整串文本 + 约定路径 `load` + 字符串反射**」，**P8 全部拆掉改回正规表**（见 §8）

### 3.5 表现层纪律

- **表现层只读运行期状态，不改战斗逻辑**（**唯一例外**：为拿状态新增**只读属性**）
- **几何量 / 颜色 / 时长 / 音效名全用 `[Export]` 或表**
- ⚠️ **残影/特效/掉落物不能进单位列表**（`enemy_units` 等）—— 否则被清场/计数/伤害逻辑误伤。
  **P6c 的做法**：复制出模型后**递归删掉全部 `CollisionObject3D`/`Unit`/`AnimationTree`/`AnimationPlayer`** + **退出所有分组**，只挂 `CurrentScene`

### 3.6 环境 / 流程

- ⚠️ **不要用 `stop_project`** —— 它**全局生效**，会杀掉别人正在跑的自测。要停实例就**按 PID 关**那个子进程
- ⚠️ **不要关 Godot 编辑器** —— 它是 **MCP 的宿主**
- **自测跑完必须删 `user://selftest.flag`**
- **每完成一批就 `git commit` + `push`** —— **有代理没提交就中断，成果差点丢**
