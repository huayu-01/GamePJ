# 基地、关卡与整局流程

当前正式主循环已经覆盖基地、三关和再次出发。本文记录现行职责与规则；旧单关、无基地、旧配额及历次日志见 [历史原文](archive/reference-before-2026-10-21/stages.md)。验证状态见 [当前快照](SESSION-SNAPSHOT.md)。

## 玩家流程

```text
Base 基地：角色展台 → 所属武器 → 木桩练习／能力卡／携带符文
  → 互动出击门 → 配置摘要确认 → Expedition
  → 探索 → 互动节点 → 领取收益 → 挑战 → 继续探索
  → 自由探索时打开首领门 → 首领战 → 互动降临节点
  → 下一关（保留构筑，调用 FillVitals 回满）或整局通关
  → 结算 → 回基地 → 成长／调整配装 → 再次出发
阵亡 → 死亡动画与面板 → 整局结算 → 回基地
```

基地为 `Scenes/Levels/Base.tscn`，正式出征为 `Scenes/Expedition.tscn`，森林环境由 `Scenes/Levels/ExpeditionForest.tscn` 组合现有 NatureArena。`Main.tscn` 保留测试地形和既有回归入口。三关复用场景，顺序由 `Config/ConfigIndex.tres.Stages` 引用的 `stg_outer`、`stg_inner`、`stg_core` 决定。森林使用正式玩家、六武器配装和节点流程；模型样件的生产替换状态仍以各资产说明为准。

角色／武器选择属于基地交互；进入关卡不再额外弹旧的 Configure 流程。基地配装与记忆见 [基地与换装](base-loadout.md)。

## Stage 与 Encounter

| 管理者 | 负责 |
|---|---|
| `RunController` | 整局配装、奖励、三关推进、结算和返回基地 |
| `StageController` | 单关节点、挑战次数、隔离次数、首领压力、首领门和离场 |
| `EncounterController` | 一场挑战的波次／预算、生成、清场和失败 |

节点挑战结束后返回探索，不自动串行开启下一个节点。必须清除本场 Encounter 计入的敌人才能完成；游离怪不计入这项清场条件。

挑战开始后角色显示金色粒子和脚底标记，右上面板读取真实波次、剩余生成预算、即时额度和本场存活数。预算耗尽仍须清完本场敌人；还有预算且限定波次未出完时，波间空场不会提前完成。真清场后解除状态、播放完成绿波和音效；失败、停止、复位、死亡或退树只撤销状态。挑战中对其他有效交互按F，会得到红色波罩、音效和碰撞弹开反馈，目标不会被消耗。组件参数见[接入手册](interaction-authoring.md)，交付见[J48](archive/development-batches/character-design-j48.md)。

场景物体可挂 `InteractionComponent`，在 Inspector 选择奖励／门／出口类型；旧交互预制体仍兼容。Stage收集整个子树内的交互后端，不跨入其他Stage，支持模型容器和嵌套挂点。`NodePlacement` 与森林布点通过 `MoveTo` 一起移动宿主、模型和触发器；接入步骤与范围配置见 [交互组件](interaction-authoring.md)。

## 节点与隔离次数的唯一规则

- 每关固定目标为 **10 个普通节点：高价值2／中价值5／低价值3**，由 `StageController.EnableByLayer` 按价值层启用候选对象。
- 隔离次数由全局 `FreeChallengeBaseQuota`、`FreeChallengeMaxQuota` 和关卡序号计算：`min(上限, 初始额度 + 关卡序号 - 1)`。当前三关为 **1／2／2**。
- 仅 `SpawnsEncounter=true` 的挑战消耗隔离次数；开始挑战时增加 `ChallengesUsed`。未超额的挑战清场后不增加节点 Pressure，也不抽取额外数值词条。
- `StageDefinition` 的旧 `RewardNodeCount`／`FreeChallengeQuota` 配置已在本轮移除。它们曾被上述规则覆盖，旧表内3／4／4和2／2／1不再是调参入口。双构建、森林节点及 Main 规则比对已通过。

节点类型由 `Config/Tables/Nodes/` 定义，收益与挑战遵循“**先奖励后挑战**”：强化／进化／异化弹出相应候选，材料与恢复可即时发放，商店先完成选择；收益流程结束后，按节点开关开始挑战。节点一次性使用；降临节点只负责离场。

| 价值层 | 当前节点 | 波数 |
|---|---|---:|
| 高 | 进化、异化 | 4 |
| 中 | 强化、补给站 | 3 |
| 低 | 局外资源、恢复状态、特殊奖励 | 1 |

`NodePlacement.WavesFor` 依次读取价值标签的 `WaveCount`（多标签取最大）、节点行 `WaveCount`、价值层兜底。降临节点不刷怪，其低价值标签不代表存在一场挑战。

“武器限定池”是进化奖励的限定关系；生产节点行统一使用 `node_evolution`，不是额外一种武器节点。

## 战斗节奏与当前限制

当前普通挑战使用波次模式，上一波仅余至多1只时才允许继续开波；每波目标数由 `WaveMinEnemies`／`WaveMaxEnemies` 决定，类型上限由 `WaveMaxTypes` 决定。生成仍受可用预算、时间门槛和有效位置约束。

**波次模式当前一次性出波**，并非按 `MaxConcurrent` 将整波严格拆批。类型选择与波内单只选择均按正 `Weight` 加权；零权重不生成。有效点失败保留波内待生成数并重试；成功生成才扣预算。`MaxConcurrent` 约束非波次逐只生成，不能作为整波硬上限。

每关累计已开波数达到 `EliteBossMinWave`（当前8）后，挑战末尾可进入白板首领副本；详见 [首领](boss.md)。这不是完整首领门战。

### 游离刷怪

`StageController.UpdateAmbientSpawns` 与节点战斗并存。当前全局配置为每30秒尝试生成、每120秒增强之后生成的敌人、存活上限6；`AmbientSpawnInterval=0` 可关闭。每档增量为 `AmbientSpawnStrengthStep`，当前0.25，即倍率 `1 + 档位 × 0.25`。

游离怪不扣节点预算、不计入本场 `AliveCount` 或 `MaxConcurrent`，所以清完挑战不等于场上绝对安全。HUD 分别显示挑战敌人和游离敌人数量。

## 首领、离场与换关

首领门战、节点数值词条和战斗内计时压力分别见 [首领契约](boss.md)。通常交互受挑战者闸门约束；自由探索时可开门放弃剩余普通节点。

首领死亡后清场；有预置 `Exit` 组件时，在原设计位置激活同一出口，否则仍在首领门附近生成降临节点并落地。出口开局隐藏禁用、不占10个普通节点配额，只在首领结束后接受互动，不自动换关。前两关离场后重置单关状态、回出生点并回满，保留本局构筑；末关离场执行通关结算。正式换关通过 `ApplyStage → ResetStage` 保留并重新隐藏预置出口，只回收运行期生成的出口。

首领结束后冻结本关统计与游离生成；首领门打开后不再领取普通节点，收尾阶段只接受离场；末关提示明确返回基地。上述边界已通过 [J44流程专项](archive/development-batches/character-design-j44.md)，完整战斗试玩仍需另验。

## 整局记录、成长与再次出发

整局记录累计各关有效游戏时间与挑战次数，已完成关卡冻结一次，死亡或通关只结算一次；暂停和首领结束后的离场等待不计时。专项已验证三关累计60秒／6次挑战、收益去重和死亡确认后真实返回。旧实现直接读取末关状态，旧日志不能替代本轮跨关证据。

节点材料收益会即时写入局外资源；整局结算的进度、挑战和通关收益由整局编排负责。能力卡承担碎片的解锁、升级、激活与额度扩增，详见 [能力卡](ability-cards.md)。旧 BaseScreen 五项永久强化页已退出当前基地入口。

装备记忆、局外进度、设置和符文各自持久化；不得用旧测试指纹覆盖玩家后来保存的配置。基地练习目前不完整施加携带符文效果，不能以木桩结果保证进关后所有符文手感一致。

## 后续地形设计边界

节点是需要实际接近的场景对象，可达性会影响奖励选择。当前跳跃可用，主循环不依赖构筑解锁地形。用户提出的“初期不能跳跃／高价值节点需跳跃／雷系打碎可攻击岩石后进入区域”属于后续探索方向，尚未定案、未实施；统一记录在 [完整玩家体验计划](player-experience-plan.md)。

新增地形前须明确基础必经路线、可选构筑路线与失败回退，分别验证节点、首领、护卫及出口的可达性。普通敌人的严格有效点验证不能替代交互点与首领生成的专项验收。
